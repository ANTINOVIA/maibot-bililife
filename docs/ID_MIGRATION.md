# 插件 ID 迁移与回滚

当前唯一运行标识是 **`ANTINOVA.maibot-bililife`**，区分大小写。版本保持 `0.2.6`。
GitHub 仓库所有者仍是 `ANTINOVIA`；这两个名称相互独立，不应自动改写仓库地址或许可证署名。

旧安装的 ID 为 `local.maibot-bililife`。直接将新包当作另一个插件导入，会产生独立数据目录，
因此已有安装应先迁移原有目录，而非同时启用两份插件。历史备份、旧 Git 标签及本说明中的
旧标识仅用于追溯和回滚；运行清单和页面地址均使用新标识。本包不提供自动 ID 迁移或恢复脚本。

## 新路径

| 用途 | 路径 |
| --- | --- |
| 源码 | `/opt/maibot/plugins/ANTINOVA_maibot-bililife` |
| 数据、配置、独立扫码凭据及模型密钥 | `/opt/maibot/data/plugins/ANTINOVA.maibot-bililife` |
| 临时媒体目录 | `/opt/maibot/temp/plugins/ANTINOVA.maibot-bililife` |
| WebUI 总览 | `/extensions/ANTINOVA.maibot-bililife/overview` |
| 后端前缀 | `/api/webui/plugins/runtime/webui/ANTINOVA.maibot-bililife/overview/` |

## 手动迁移

由管理员在维护窗口内执行。先核实实例实际根目录与宿主的目录监听行为；以下路径对应 `/opt/maibot` 标准布局，不要直接套用到其他实例。

1. 在旧插件页面暂停任务、停止新发布，等待在途请求结束或保存未知状态，并生成 SQLite online backup。通过宿主界面禁用旧插件，确认 Runner 已停止。在服务器受保护位置备份完整源码、`config.toml`、专属数据和临时目录；记录数据数量、配置与凭据文件哈希，凭据本身不输出或传输。
2. 核对新安装包 SHA256，确认目标目录不存在且路径不经过符号链接。目标已存在时先检查是否已有第二份实例，不直接覆盖或合并两套数据库。保持迁移期间的插件禁用状态，避免目录监听提前加载。
3. 将旧源码目录 `plugins/local_maibot-bililife` 移至表中的新源码目录，将旧数据目录 `data/plugins/local.maibot-bililife` 移至新数据目录；如需保留临时媒体，同样迁移旧 `temp/plugins/local.maibot-bililife`。在新源码目录更新安装包内容，保留原 `config.toml` 和专属数据；不要用空目录替代已有数据库。
4. 通过宿主插件管理界面识别并启用新 ID。先核对账号、模型路由、数据数量、凭据文件哈希、已有额度和发布状态；确认只运行新 ID 后再按原意恢复任务与发布开关。

目录移动不能代替数据库核对。不得重置额度、改写历史记忆或将未知发布重新提交；也不直接修改未知的宿主数据库表。迁移遇到不明实例布局、提前加载或重复实例时应保持禁用，由管理员先确认状态。新安装无需迁移，直接使用新 ID 即可。

## ID 回滚

仅在需要恢复旧插件身份时手动回滚；普通同 ID 源码回滚见 [运维文档](OPERATIONS.md#数据备份与恢复)。不要将旧 ID 的源码备份直接覆盖到新 ID 目录。

暂停任务、停止新发布并从宿主界面禁用新实例，备份当前数据后，将**当前**数据移回旧命名空间，并恢复与当前数据库、配置兼容的旧源码和原 `config.toml`。保留迁移之后新增的经历和已确认或未知的发布状态，不用迁移前数据库快照覆盖当前 outbox。旧目标目录已存在时先检查冲突，不自动合并。

没有自动回滚或配置降级工具；管理员须先核对目标版本支持的数据库迁移与配置格式。不兼容时保持插件禁用，不直接启动旧源码。

迁移完成后请更新书签和外部调用方的插件 ID。旧页面和接口不会继续作为运行别名提供服务。
