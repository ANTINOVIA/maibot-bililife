# 主聊天发起浏览

主聊天模型理解自然语言并调用工具，插件不匹配聊天关键词或截取固定句式。原有后台定时浏览保留；此功能不写入 A-Memorix。

## 工具

- `bililife_browse(mode="browse", share_after=false)`：依据兴趣发现一条未处理的新视频。
- `bililife_browse(mode="search", query="机器人", share_after=true)`：搜索、选片、获取真实字幕/画面并理解，完成后按明确要求分享。
- `bililife_browse(mode="watch", query="BV...", share_after=false)`：理解指定视频，支持 BV 号、`https://www.bilibili.com/video/BV...?p=1` 和 HTTPS b23.tv 短链接。短链接只读取一次跳转，目标须是有效 B 站视频。已有完整理解时明确标记 `cached=true`，不声称新看完。
- `bililife_task_status(request_id="...")`：查询本会话请求；省略编号查询最近一次。查询本身不发送消息。

目标会话使用已有视频分享或空闲浏览配置。手动浏览不要求启用空闲浏览，也不等待空闲阈值和浏览间隔；浏览模块开关、登录状态、暂停、活跃时段、休息、允许范围及资源预算仍生效。搜索词无需字面包含允许主题，但候选内容须通过主题/UP 范围检查。

主聊天工具的 `share_after` 为必填参数，需按用户实际要求填写。API 兼容默认 false。进行中的同一搜索可以追加 true，不创建重复浏览；不会通过重复调用将已记录的 true 改回 false。搜索阶段先排除超出时长的候选，并将具体查询条件传给语义选片模型。

## 执行与回调

1. 校验真实调用会话及参数，事务创建请求和根任务，返回 `request_id`、`queued`。
2. 复用原有 `discover → watch → memory` 执行器，将 `origin=chat_command`、请求编号及会话传递给子任务。指定视频直接从 watch 开始。
3. 等待实际内容理解及插件本地经历保存；搜索完成或加入队列不算看完。没有新片、内容不足、登录失效及模型失败均返回真实失败。
4. `share_after=true` 时经现有统一服务尝试分享，保留真实发送回执。明确要求已由主聊天记录，不再靠下一轮模型重新猜测；未要求分享则只交回内容供交流。
5. 用 `maisaka.proactive.trigger` 将具体内容、个人感受、证据范围、缓存标记与发送结果交回原主聊天。主聊天按人设组织回复。回调 `queued` 仅代表宿主接收，不等于聊天已发送；须结合主聊天/QQ 回执验收。

请求状态为 `queued/running/sharing/completed/failed`。`completed` 表示内容理解完成；分享是否成功另看 `result.sharing.sent`。同会话重复的进行中请求复用一个任务，不同请求提示当前忙碌。指定旧视频仍可读取，但必须明确是缓存。

本地经历整理失败时仍保留已完成的内容理解，单独报告整理失败；分享仍须满足活跃经历要求。现有分享冷却及每日上限适用于这些任务，受限时明确记录 blocked，不声称已发送。

手动浏览不自动创建 B 站评论、公开回复或自适应计划。长任务在后台执行，不阻塞主聊天工具 RPC。请求最长 30 分钟，受活跃时段截止限制。

## 故障恢复与边界

请求保存在 SQLite `chat_requests`，迁移不覆盖历史视频、记忆、配置或凭据。任务恢复沿用原执行器。分享发送前持久化阶段；进程中断后不自动重新发送。回调投递先认领，超时或投递时中断标记 unknown，不自动重复唤醒，用户仍可通过状态工具读取结果。

QQ 适配器提供可选 `ark_delivery_status` API，按目标、卡片内容及发送时间读取回执。明确 HTTP 4xx 拒绝记录 failed，并保留 `40034126` 等错误；旧适配器、不匹配、超时等情况仍为 unknown。没有自动文字降级，也不以更换模板编号规避平台权限。

本功能复用字幕/抽帧理解，并非完整实时音视频播放；结果含实际覆盖范围。它不等于原生长期记忆接入。

## 验证

离线测试覆盖三种模式的完整子任务链、明确/未要求分享、请求绑定、并发重复、旧结果标记、无新结果、理解失败、只有元数据、状态隔离、回调超时及重启不重复发送。真实部署还须分别验证 QQ 自然语言调用、实际 B 站内容获取、主聊天完成反馈和 QQ 发送回执；离线通过不代表平台权限可用。
